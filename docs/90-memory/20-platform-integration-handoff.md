# Arda / Karda 平台对接交接与长期记忆

决策日期：2026-11-24。两仓采用同一口径。这里是后续对接的恢复入口；[I0–I6 历史清单](../70-workplan/70-integration-closure-20261123.md)保留已做工作和验收证据。历史清单里的旧产品待办不构成本轮范围。

**边界：** 产品仓只负责消费平台配置、落实本仓接口和复验。平台代码、服务器变量、边缘路由和正式客户授权由平台或其运营人员管理；产品可以提交问题和证据。旧业务模块建设与验收、演示功能、页面重建、Karda 加工/向量化/问答功能整改均不在这份清单。通用 AI 计费接口仍在范围内，不为验收重建任何旧业务功能。

**已完成基线：** Arda v0.13.8、Karda v0.11.9 已生产发布。正规域名分别为 `arda.ruyin.work` 和 `karda.ruyin.work`。公开状态与套餐入口、匿名权益 401、监控就绪均已验收；不把它们重新列成待办。四档公开、年付按十个月、Free 下架为已交付配置。显式角色及所有者保护已部署；测试成员的真实授权链路仍待验收。

## 产品仓现在能做的，以及何时关闭

- **I2 本仓：** 对显式角色、默认角色、无角色、Guest、租户隔离做本地或隔离回归，修本仓差异。不把模拟测试记作平台席位或消息生产验收通过。
- **I5 本仓：** 对已保留接口的存储待投递记录、回执匹配、幂等及代用户鉴权做本仓回归，发现缺口只修通用对接层。保留线上既有套餐的兼容路径，未经批准不迁移真实客户套餐、权限或用量。
- **恢复规则：** 对应平台契约、适用配置版本及可复核证据到位后，才启动该批联调。I1 另须按用户决定恢复；不主动复测或反复要求登录。两仓分别记录环境、版本、脱敏证据及结论。平台工单关闭、本仓代码合并、公开探针通过都不能代替生产对接验收。
- **I6 关闭：** 逐项标成「生产已验收」「待平台交付」「用户暂缓」或「随重构淘汰」；允许移交未完成的平台事项及其恢复条件，不把它们标成已验收。除本表外，不扩展产品功能任务。
